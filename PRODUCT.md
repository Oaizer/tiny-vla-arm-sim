# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML, CSS, and JavaScript in the repository. GitHub Pages is a possible publishing target; publication is not yet confirmed.

## Users

Inferred from the request: robotics and machine learning readers who need a clear, portfolio-ready record of this simulated VLA and world-model project.

## Product Purpose

Inferred from the request: collect project iterations, trial videos, and measured statistics in one page so a visitor can compare the work over time.

## Positioning

The evidence comes from a small VLA and JEPA-style world-model project evaluated with an existing PyBullet arm simulator. Results include both successful and unsuccessful comparisons, and the models remain outside the arm controller unless an experiment shows a clear gain.

## Operating Context

The project runs in simulation only. The portfolio page belongs in this repository and should use results and media already generated by the experiment. The user asked to keep documenting iterations as work continues.

## Capabilities and Constraints

All reported trial data are simulated. Do not imply physical-robot testing. Separate prediction quality, candidate contact ranking, and end-task completion. Label examples and videos as selected examples, and preserve negative results and sample sizes. Use mostly plain English consistent with the project's STE100 writing preference.

## Evidence on Hand

- V1 world-model results and arm trial summaries in `artifacts/world-v1/`.
- V2 frozen controller comparison in `artifacts/world-v2/`.
- V3 contact prediction and candidate ranking report in `artifacts/world-v3/contact/`.
- V4 targeted contact prediction and independent ranking report in `artifacts/world-v4/contact/`.
- Matched simulation trial videos in the sibling `tiny-vla-impact-videos` output folder.
- V5 reranker experiment is in progress; include it when its fresh test is complete.

## Product Principles

- Show evidence and limits together.
- Make comparisons easy across iterations.
- Keep examples tied to measured results.
- State that all work is simulation-only.
- Update the record after each experiment.
